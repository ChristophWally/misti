Summary
This PR implements the PRD to display tags from the normalized metadata model and fetch optional translation tags via a small RPC. Core tags retain their distinctive visuals; optional tags render as succinct, text‑only chips using shorthands with tooltips. Legacy paths and the feature flag were removed to avoid duplication — the app now builds strictly against the v3 structure.

Why
The database now stores tags in normalized tables to reduce storage and improve performance. The UI should read from that model consistently and efficiently, with short labels for optional tags and tooltips for clarity. This PR aligns the frontend with that model and keeps the codebase clean.

Changes
- Supabase
  - Adds RPC public.app_get_translation_tags(p_translation_ids uuid[], p_limit int) → per‑translation tags as objects: { value, shorthand, label, description, attribute }.
  - Seeds shorthands for common optional tags (High, Med, Original, Academic, Technical, Verified, Aesthetic, Positive, Quality, Family, Architecture, Alt, Leaving, Meeting, Simple).
  - Seeds human‑readable descriptions (tooltips) for those tags.
- Frontend
  - Adds lib/tag-display-map.js to map RPC tags to chips; filters out test_* values.
  - EnhancedDictionarySystem: adds loadWordsNormalized (no legacy fallback).
  - DictionaryPanel: always uses normalized loader.
  - WordCard: renders compact optional chips per translation and keeps restriction indicators.
  - Build passes locally (viewport deprecation warnings only).
- Documentation
  - Archives pre‑v3 tagging docs to backup-archive/2025-09/ (arrays/GIN era).
  - Updates audio implementation guide and DEV_LOG with v3 notes.
  - Adds v3‑aligned note to migration tools architecture.
